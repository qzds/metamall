### 已落地的美术调整

1. 全屏画布，前景到达平台/角色、中景品牌岛、后景城市/星体形成纵深；主标题放左侧，门头标签放到真实 3D 锚点。
2. 地标环和旋转晶体抬高，不挡住三个种子店。新增店真实追加岛屿与桥，底部导视随发布数据增长。
3. 三品牌改变建筑轮廓、陈列和材质：云裳暖拱廊；极简冷色矩形悬挑；青禾温室骨架与绿植。木/石/织物使用程序纹理，不依赖远程图片。
4. 有边界的角色行走、相机拖动、E 进店、商品拾取/详情/旋转；存在本机访客和行人，不宣称多人联网。
5. 反射池、环境反射、阴影和辉光集中使用。流畅模式关闭高成本效果，保留完整交互。
6. 建店参数包含风格、布局、宽深、灯光、种子和来源商品；预览/正式共用 `mall/scene.py` + `store-world.js`。连续结构变化会释放旧场景资源。

### 当前实测

Chrome 155 / Iris Xe / DPR 1；线上四家公开店；1440×1000 与 1920×1080；预热 1 秒 + rAF 采样 3 秒。高清开启反射 512、阴影 1024、辉光：商圈约 **35–36 FPS**，店内约 **54–60 FPS**，建店器约 **59–60 FPS**。1920 流畅模式约 **60 FPS**。商圈 691 calls / 108,087 三角形，含反射/阴影/后处理全部通道。

12 次建店器风格重建后纹理数稳定在 33；22 项 Django 测试通过。独立文件 SQLite 并发验证：8 请求争抢最后 1 库存/1 券只生成 1 单，4 并发取消只恢复一次，同 token 双提交仅 1 单。线上角色入店、立体商品选择、改数量、领券/核销、模拟支付与 Admin 已跑通，测试路径无页面异常或 404。原始记录见 `验证数据/`。

这些是单台核显机器的短样本；没有将自动脚本约 23 秒当作人工三分钟答辩实测。当前款式模型仍是类别示意，试衣区域为道具；多人联网和精准试衣不在本次实现范围。新版 PPT/PDF 和最终 Word 报告全部使用 3001 实机截图。

## 以下为 v2 历史记录（不作为当前性能与画面依据）

> 目的：参考成熟元宇宙/虚拟零售项目的场景设计，指导本项目的 3D 商圈与店铺优化。

## 1. 案例观察

| 案例 | 场景设计要点 | 对本项目的启发 |
|---|---|---|
| Mall of the Metaverse（迪拜，Decentraland） | 多层购物中心、入口即娱乐设施、品牌主力店、电梯/楼层导视、可点击商品跳转电商 | 入口要有“到达感”；用垂直导视和楼层/区域标识组织动线 |
| Metajuku（Republic Realm） | 16,000 平方英尺中庭式商业街，开放中心、两侧主力店、悬浮商品装置；因性能限制每家只展示约 6 件 | 中庭/街道 + 两侧店铺；商品数量克制；用“悬浮/发光”制造记忆点 |
| TX 淮海（上海） | 四层透明曲面连廊、中央“DNA 树”连接三层、LED 墙、深灰/蓝/白科幻色 | 一个强中心装置 + 连续发光界面；暗色底 + 冷暖对比 |
| Nexus Market District（Decentraland） | 商铺/画廊/主力店围绕共享活动广场，明确风格指南和店面租赁单元 | 先定“广场/街道 + 单元店面”的模块化布局，再谈品牌差异 |
| Hyperfy | Three.js + PhysX；世界内实时搭建、Place 传送、Avatar、App 组件；强调可自托管 | 场景要可组合、可传送；不要把所有内容塞进一个巨大场景 |
| Meta Horizon Central / Connect | 中央社交枢纽、传送门集合、清晰分区、20 秒内进入 action、强导视、季节性更新 | 入口 20 秒内让用户知道“去哪、怎么进店”；用传送门/地标 |
| The Sandbox 社交 Hub | 开放空间与探索角落平衡；用亮色块吸引、暗色表示负空间；传送门做远距离移动；天空盒定情绪 | 用明暗和发光引导动线；传送门/门面就是“入口 affordance” |
| Roblox Gucci Garden / Nikeland | 品牌叙事房间 + 小游戏 + 试穿/购买；弱叙事会显得空；用户互动是核心 | 每家店要有品牌个性和一个可互动点，不能只是贴图门面 |
| Spatial / MetaLibrary 研究 | 室内尺度约为真实 2 倍、高天花、曲线/对称、大窗、克制配色，减少幽闭感 | 店铺尺度要偏大、天花要高、灯光分层，避免“黑盒子” |

## 2. 提炼出的 8 条原则

1. **到达广场 + 强地标**：用户第一眼要知道“这是哪、往哪走”。本项目用尽端发光传送门作为地标。
2. **街道/中庭纵深**：不要平铺一排门面；两侧店铺 + 透视消失点，才有 3D 感。本项目改为霓虹街道。
3. **明确导视**：门头、垂直刀旗、地面光带、悬挑编号；用户不需要猜哪扇门能进。
4. **冷暖分层灯光**：街道冷色环境 + 店铺暖色橱窗；商品用重点光，环境用低照度。
5. **反射与雾气**：湿地/镜面地板、雾、光柱、粒子，是低成本高回报的“未来感”来源。
6. **社交存在感**：没有人的商场像仓库；加入行人/购物者/导购，哪怕是低模。
7. **品牌叙事**：每家店至少有一个差异化视觉锚点（颜色、橱窗、道具、商品），不能只是换色。
8. **性能克制**：单店只展示 4–6 个商品；重复物体 instancing；反射纹理 512；目标 45–60 FPS。

## 3. 本轮落地改动

- 商圈从“平铺门面”改为**霓虹商业街**：两侧错落门面 + 尽端发光传送门 + 高天花灯带。
- 加 **Reflector 镜面地板**、地面光带、雾、悬浮粒子、传送门旋转环。
- 每家店加 **垂直刀旗导视**、暖色橱窗、模特、商品海报、门头光晕。
- 加 **低模行人**，让商圈有“营业中”的社交存在感。
- 店铺页改为**暗色旗舰店**：高天花、线性灯、背光商品墙、镜面地板、模特、收银台、试衣间。
- 实测（本机 Iris Xe、1920×1080 窗口）：商圈约 **50 FPS**，店铺约 **55 FPS**（含反射/阴影）。
- 建店器实时预览共用同一 `store-core.js`，改店名/品牌色/模板/来源商品会实时变化。

## 4. 后续可继续优化

- 给每家店加一个“品牌互动点”（试穿镜、AR 试衣、扭蛋/打卡）。
- 传送门加目的地预览/楼层导览。
- 给商品画框加 hover 高亮与“查看详情”浮层。
- 低配设备提供“关闭反射/降低像素比”的质量开关。
- 用实机截图替换 PPT 里的概念图。
